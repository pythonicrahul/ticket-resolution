# FR-04 · Search over the documentation, for agents

Spec written from `docs/PRD.md` FR-04 with prompt PR-06 v1.0. Module: `src/ticketing_agent/api.py`, over `retrieve.Retriever` (FR-10, row 5).

## 1 Purpose

"The system shall provide agents with a search over the documentation that matches by meaning rather than exact words, returning ranked passages with their doc_id. **Agents' private answer files shall not be indexed.**"

PRD acceptance criterion: *"my deployment keeps dying" returns `DOC-DEPLOY-001` in the top 3.* The evidence is Sofia's and Ines's interviews and the Stage 1 disagreement about whether the documentation is the problem: it is not, finding things in it is.

This is a `Should`, and it is the one feature in the PRD aimed at the **agents** rather than at customers. It shares the retrieval FR-10 already built, so the requirement is mostly about what is *not* exposed.

## 2 Inputs and outputs

`GET /search?q=...&k=5` → `SearchResponse`:

| field | type | meaning |
|---|---|---|
| `query` | `str` | echoed, so a logged response is self-describing |
| `results` | `list[SearchHit]` | ranked, best first; may be empty |
| `count` | `int` | how many hits, so a caller need not measure the list |

`SearchHit`: `chunk_id`, `doc_id`, `title`, `heading`, `text`, `score` (rounded), `rank`.

## 3 Decision rules, in order

1. **Only `documentation.json` is searchable.** The index is FR-10's, built from `DOCS_PATH` alone. `ground_truth_responses.json` — the agents' own past answers — is never indexed and never returned. That file is the one the requirement singles out, and it is also the file that would make the evaluation meaningless if the system could read from it.
2. **Meaning, not words.** The same embedding retrieval as FR-10, so "my deployment keeps dying" reaches `DOC-DEPLOY-001` without sharing a word with it.
3. **No relevance threshold by default.** FR-10's threshold exists to stop the *drafter* answering from weak passages; an agent searching is better served by seeing the best matches and judging for themselves. `min_score` is available for a caller who wants FR-10's behaviour.
4. **`k` is bounded** to `[1, 20]`: a request for a thousand passages is a mistake or an attack, and answering it would read the whole corpus into memory.
5. **An empty query is a 400**, not an empty result. "Nothing matched" and "you asked nothing" are different answers and an agent should be told which.
6. **Retrieval failure is a 503**, with no detail beyond the type — the index being unavailable is an operational fact, not something to explain to a caller.
7. **Search is read-only and writes no decision row.** It takes no decision about a ticket, so FR-13 has nothing to record; the API's own access log is the record that a search happened.

## 4 Failure behaviour

- **Missing data:** no `DOCS_PATH` → the app refuses to start, rather than serving an empty index that looks like a working search with no results.
- **Empty retrieval:** `200` with `results: []`. Returning nothing is a valid answer (FR-10) and the count says so.
- **Model provider error:** not applicable — search makes no provider call. It works during an outage, which is when an agent most needs it.
- **Invalid model output:** not applicable.

## 5 Decision-log fields

None (rule 7).

## 6 Acceptance tests

Named `test_T_FR04_n_...`.

1. **T-FR04-1** The PRD's own criterion: `"my deployment keeps dying"` returns `DOC-DEPLOY-001` within the top 3.
2. **T-FR04-2** Results are ranked, carry `doc_id` and `chunk_id`, and `count` matches the list.
3. **T-FR04-3** Matching is by meaning: a query sharing no content word with the article still finds it.
4. **T-FR04-4** No hit ever comes from `ground_truth_responses.json` — over every expert answer's distinctive phrase, nothing in the corpus returns it.
5. **T-FR04-5** `k` outside `[1, 20]` is rejected; the default is 5.
6. **T-FR04-6** An empty or whitespace query is a 400.
7. **T-FR04-7** A retrieval failure is a 503 and does not leak the exception message.
8. **T-FR04-8** Search makes no provider call and writes no decision-log row.

## 7 Open questions

- **No authentication.** The API is unauthenticated, which is fine for a capstone on a laptop and not fine anywhere else: `/queue` exposes customer text. The deployment notes should say so, and the governance declaration should record it as an accepted risk rather than an oversight.
- **No query logging.** Nothing records what agents search for, so the "no-hit report" the PRD imagines (a cluster of questions with no article) cannot be produced yet. Worth a row of its own; the data would tell CloudServe what to write next.
- **The threshold default differs from the drafter's**, deliberately (rule 3). If agents report noise, the answer is `min_score`, not a global threshold.
